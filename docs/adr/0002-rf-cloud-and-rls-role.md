# ADR-0002 · РФ-облако, 242-ФЗ и роль приложения в БД

- **Статус:** Принято
- **Дата:** 2026-06-20

## Решение

- **Локализация (242-ФЗ):** prod и staging (при реальных ПДн) — только РФ-регион (Yandex Cloud / VK Cloud / Selectel). Объектное хранилище ПДн и бэкапы — в РФ. Трансграничной передачи ПДн в v1 нет.
- **Роль приложения в Postgres:** prod/staging приложение ходит в БД под отдельной ролью `conf_app` (`NOSUPERUSER`, **без `BYPASSRLS`**). Это **инвариант**: без него политики RLS (Фаза 2) молча игнорируются. Запись в Definition of Done Фазы 2.
- **Конфигурация только через env**, секреты не в образе. `.env*` (кроме `*.example`) в `.gitignore`. Per-tenant секреты (Фаза 3+) — шифрование at-rest (AES-GCM, мастер-ключ из env, ротация по key-id).

## Следствия

- В Фазе 2 миграция создаёт/проверяет роль `conf_app` и применяет RLS-политики.
- Бэкапы: ежедневный `pg_dump`, внеочередной перед каждой прод-миграцией; restore репетируется до рубежа MVP.
